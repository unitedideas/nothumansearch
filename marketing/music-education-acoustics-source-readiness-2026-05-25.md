## Segment

This segment is narrower than the older education, local-events, publisher,
and lifestyle briefs. It is for music-education sites, acoustics explainers,
theory/history resources, course platforms, cultural archives, and specialist
reference products whose pages may become source material for agents answering
music, tuning, history, or learning questions.

Useful owner-side angle:

- `llms.txt` should identify canonical lesson, archive, citation, curriculum,
  licensing, and correction/update pages.
- Schema.org should distinguish courses, articles, datasets, organizations,
  events, people, and creative works where the owner controls those facts.
- Feeds or APIs are useful where lessons, notation assets, datasets, or
  archive records change over time.
- OpenAPI, MCP, or structured API metadata should exist only where the owner
  intends automated access.
- Robots policy should state whether major AI crawlers are allowed.
- High-score owners should route to free monitor registration, public report
  sharing, and badge/report proof.
- Partial-score owners should start with `/score` and a missing-surface
  checklist before any paid remediation.

## Draft Brief

Agents answering music-theory, tuning-history, or acoustics questions need a
source contract, not a copied explanation.

For music-education sites, cultural archives, course platforms, notation
tools, and acoustics references, the machine-readable surface should say which
lesson, dataset, archive, citation, licensing, and update pages are canonical.
Not Human Search does not certify the theory, pedagogy, historical claim, or
audio analysis. It checks whether an agent can inspect the public source before
using it.

High-score owners should use the public report, badge, and free monitor path.
Partial-score owners should run `/score`, fix missing machine-readable
surfaces, and only then consider remediation.
